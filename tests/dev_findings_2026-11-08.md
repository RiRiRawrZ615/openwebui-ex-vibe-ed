## 1. Loop guard

Problem in screenshot 1: the agent read a trimmed turn, concluded nothing prior existed, and
then felt it "must still make a function call", spending a turn on the audit tool for nothing.

Two causes, both fixed in `backend/open_webui/utils/ex_loop_guard.py`:

- The reasoning similarity check counted any similar pair as a loop, including a plan restated
  while the agent kept making progress. `scan()` now records how many tool calls ran between
  consecutive similar blocks (`gap_progress`) and only trips when a pair is similar **and** no
  call ran between them (`stalled_pairs`). Similar thinking with progress returns `clean`.
- The note read as a command. `steering_note()` now says explicitly that it is an observation
  and lists a plain-text answer as a valid way to close the turn. `refused_call_note()` was
  changed the same way, so a refused call no longer forces another call.

## 2. Journal tool

`backend/open_webui/tools/builtins/ex_journal.py` (new dev builtin). Exposes `index` and `read`
so the pointer the prompt already prints ("retrieve with ex_journal.read(entry=N)") resolves to
a real tool. Resolves the chat from the request, falls back to the newest journal file, and
reads with plain file access, never under the fork lock.

Not registered yet: `builtins/manifest.json` is generated by `tools/convert_builtins.py` and is
not hand-edited per the fork rules. Either regenerate the manifest or add the tool through the
UI. The file itself is ready.

## 3. Context gate

The refusal in screenshot 3 is the engine's, and a prompt larger than the window cannot be
served, so "bypass" cannot mean raising the ceiling above 262144. It means stop refusing and
start evicting, which is what the fork's own design says and what was never wired.

- New `backend/open_webui/utils/ex_evict.py`: `evict_to_fit()` drops, in order, old tool
  output (stub), then whole oldest tool turns, then oldest conversation turns. Tool call and its
  results leave as a unit so pairing survives. Head, newest turn, and any `[journal]` block are
  never evicted. If nothing load bearing is left it reports `blocked_reason` instead of an error.
- `apply_overflow_policy()` in `ex_context_window.py` now calls it when stubbing is not enough,
  so the middleware path evicts per turn instead of falling back to summarisation.
